================================================================
OLRAC ADVERSE - DEPLOYMENT GUIDE (AWS EC2 + GODADDY + CI/CD)
================================================================

OVERVIEW
--------
Host the entire stack on a single AWS EC2 instance using your
GoDaddy domain olracads.com. Nginx serves both React frontends
as static files and proxies /api and /uploads to FastAPI (Gunicorn).
GitHub Actions auto-deploys on every push to main.

  Domain Layout:
    olracads.com         -> React client site
    admin.olracads.com   -> React admin site
    (no separate API subdomain — /api is proxied by Nginx on both)

  Stack on EC2:
    Nginx                -> reverse proxy + static file server
    Gunicorn + Uvicorn   -> FastAPI backend (port 8001, internal only)
    PostgreSQL           -> database (local on EC2)
    Let's Encrypt        -> free SSL certificates
    GitHub Actions       -> CI/CD auto-deploy on push to main


================================================================
PART A — FIRST-TIME SERVER SETUP (run once)
================================================================

----------------------------------------------------------------
STEP 1 — SSH INTO EC2 AND INSTALL SYSTEM DEPENDENCIES
----------------------------------------------------------------

  ssh -i your-key.pem ubuntu@<EC2-IP>

  sudo apt update && sudo apt upgrade -y

  # Python
  sudo apt install -y python3 python3-pip python3-venv

  # Node.js 20 LTS
  curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
  sudo apt install -y nodejs

  # Nginx, Certbot, PostgreSQL, Git, rsync
  sudo apt install -y nginx certbot python3-certbot-nginx \
    postgresql postgresql-contrib git rsync

  # Playwright system deps (for PDF invoice generation)
  sudo apt install -y libnss3 libatk1.0-0 libatk-bridge2.0-0 \
    libcups2 libdrm2 libxkbcommon0 libxcomposite1 libxdamage1 \
    libxfixes3 libxrandr2 libgbm1 libpango-1.0-0 libcairo2 libasound2


----------------------------------------------------------------
STEP 2 — EC2 SECURITY GROUP (AWS Console)
----------------------------------------------------------------

In AWS Console -> EC2 -> Security Groups -> Inbound Rules,
ensure these ports are open:

  Port 22   (SSH)
  Port 80   (HTTP)
  Port 443  (HTTPS)


----------------------------------------------------------------
STEP 3 — POSTGRESQL DATABASE
----------------------------------------------------------------

  sudo -u postgres psql

  -- Inside psql:
  CREATE DATABASE olrac;
  CREATE USER olracuser WITH PASSWORD 'YourStrongPassword';
  GRANT ALL PRIVILEGES ON DATABASE olrac TO olracuser;
  \q

Your DATABASE_URL:
  postgresql://olracuser:YourStrongPassword@localhost:5432/olrac


----------------------------------------------------------------
STEP 4 — UPLOAD PROJECT FILES TO EC2
----------------------------------------------------------------

Clone directly on EC2 from GitHub:

  git clone https://github.com/roshannandhu/Olrac.git /home/ubuntu/olrac

Or rsync from your local machine (Windows: use Git Bash or WSL):

  rsync -avz --exclude 'node_modules' --exclude '__pycache__' \
    --exclude '.env' --exclude 'venv' --exclude 'dist' \
    -e "ssh -i your-key.pem" \
    /path/to/olrac/ ubuntu@<EC2-IP>:/home/ubuntu/olrac/


----------------------------------------------------------------
STEP 5 — BACKEND SETUP
----------------------------------------------------------------

--- 5a. Python virtual environment ---

  cd /home/ubuntu/olrac/backend
  python3 -m venv venv
  source venv/bin/activate
  pip install -r requirements.txt

  # Install Playwright browser (needed for PDF invoice generation)
  python -m playwright install chromium
  python -m playwright install-deps chromium

--- 5b. Create the backend .env file ---

  nano /home/ubuntu/olrac/backend/.env

Paste and fill in real values:

  DATABASE_URL=postgresql://olracuser:YourStrongPassword@localhost:5432/olrac

  JWT_SECRET_KEY=<run: openssl rand -hex 32>
  JWT_ALGORITHM=HS256
  JWT_EXPIRY_MINUTES=1440

  SMTP_HOST=smtp.gmail.com
  SMTP_PORT=587
  SMTP_USER=your@gmail.com
  SMTP_PASSWORD=your-gmail-app-password
  SMTP_FROM_NAME=Olrac

  GROQ_API_KEY=your-groq-api-key
  GROQ_MODEL=llama-3.3-70b-versatile

  WHATSAPP_ADMIN_NUMBER=919876543210

  DEFAULT_ADMIN_NAME=Admin
  DEFAULT_ADMIN_EMAIL=admin@olracads.com
  DEFAULT_ADMIN_PASSWORD=YourStrongAdminPassword
  DEFAULT_ADMIN_SYNC_PASSWORD=true

  CORS_ORIGINS=https://olracads.com,https://www.olracads.com,https://admin.olracads.com
  CORS_ORIGIN_REGEX=

--- 5c. Create systemd service for FastAPI ---

  sudo nano /etc/systemd/system/olrac-backend.service

Paste:

  [Unit]
  Description=Olrac FastAPI Backend
  After=network.target postgresql.service

  [Service]
  User=ubuntu
  WorkingDirectory=/home/ubuntu/olrac/backend
  Environment="PATH=/home/ubuntu/olrac/backend/venv/bin"
  EnvironmentFile=/home/ubuntu/olrac/backend/.env
  ExecStart=/home/ubuntu/olrac/backend/venv/bin/gunicorn app.main:app \
    -w 2 -k uvicorn.workers.UvicornWorker \
    --bind 127.0.0.1:8001 \
    --timeout 120
  Restart=always

  [Install]
  WantedBy=multi-user.target

  sudo systemctl daemon-reload
  sudo systemctl enable olrac-backend
  sudo systemctl start olrac-backend

  # Verify it works:
  curl http://127.0.0.1:8001/health
  # Expected: {"status":"healthy"}


----------------------------------------------------------------
STEP 6 — NGINX CONFIGURATION
----------------------------------------------------------------

Both the client and admin Nginx configs proxy /api and /uploads
to the backend. No separate api subdomain is needed.

--- 6a. Client site (olracads.com) ---

  sudo nano /etc/nginx/sites-available/olrac-client

Paste:

  server {
      listen 80;
      server_name olracads.com www.olracads.com;
      root /var/www/olrac/client;
      index index.html;

      client_max_body_size 100M;

      location /api {
          proxy_pass http://127.0.0.1:8001;
          proxy_http_version 1.1;
          proxy_set_header Host $host;
          proxy_set_header X-Real-IP $remote_addr;
          proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
          proxy_set_header X-Forwarded-Proto $scheme;
          proxy_read_timeout 120s;
      }

      location /uploads {
          proxy_pass http://127.0.0.1:8001;
          proxy_http_version 1.1;
          proxy_set_header Host $host;
          proxy_set_header X-Real-IP $remote_addr;
          proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
          proxy_set_header X-Forwarded-Proto $scheme;
      }

      location / {
          try_files $uri $uri/ /index.html;
      }
  }

--- 6b. Admin site (admin.olracads.com) ---

  sudo nano /etc/nginx/sites-available/olrac-admin

Paste:

  server {
      listen 80;
      server_name admin.olracads.com;
      root /var/www/olrac/admin;
      index index.html;

      client_max_body_size 100M;

      location /api {
          proxy_pass http://127.0.0.1:8001;
          proxy_http_version 1.1;
          proxy_set_header Host $host;
          proxy_set_header X-Real-IP $remote_addr;
          proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
          proxy_set_header X-Forwarded-Proto $scheme;
          proxy_read_timeout 120s;
      }

      location /uploads {
          proxy_pass http://127.0.0.1:8001;
          proxy_http_version 1.1;
          proxy_set_header Host $host;
          proxy_set_header X-Real-IP $remote_addr;
          proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
          proxy_set_header X-Forwarded-Proto $scheme;
      }

      location / {
          try_files $uri $uri/ /index.html;
      }
  }

--- 6c. Enable and reload ---

  sudo ln -s /etc/nginx/sites-available/olrac-client /etc/nginx/sites-enabled/
  sudo ln -s /etc/nginx/sites-available/olrac-admin  /etc/nginx/sites-enabled/

  sudo nginx -t
  sudo systemctl reload nginx


----------------------------------------------------------------
STEP 7 — COPY FRONTEND BUILDS TO WEB ROOT
----------------------------------------------------------------

On EC2, build the frontend and copy to Nginx's web root.
(With CI/CD active this is done automatically — only needed
for the very first deploy or if doing a manual deploy.)

  cd /home/ubuntu/olrac/frontend
  npm install --legacy-peer-deps

  VITE_CLIENT_SITE_URL=https://olracads.com \
  VITE_ADMIN_SITE_URL=https://admin.olracads.com \
  npm run build:client

  VITE_CLIENT_SITE_URL=https://olracads.com \
  VITE_ADMIN_SITE_URL=https://admin.olracads.com \
  npm run build:admin

  sudo mkdir -p /var/www/olrac/client /var/www/olrac/admin
  sudo cp -r dist/client/. /var/www/olrac/client/
  sudo cp -r dist/admin/.  /var/www/olrac/admin/


----------------------------------------------------------------
STEP 8 — GODADDY DNS SETUP
----------------------------------------------------------------

Log in to GoDaddy -> My Products -> Domains -> DNS (olracads.com)

Add 3 A records pointing to your EC2 Elastic IP:

  Type  | Name    | Value        | TTL
  ------|---------|--------------|-----
  A     | @       | <EC2-IP>     | 600
  A     | www     | <EC2-IP>     | 600
  A     | admin   | <EC2-IP>     | 600

NOTE: EC2 Elastic IP -> AWS Console -> EC2 -> Elastic IPs.
Allocate one and associate it to the instance if not done yet
(prevents IP from changing on every instance restart).

Wait 10-30 minutes for DNS propagation, then proceed.


----------------------------------------------------------------
STEP 9 — SSL CERTIFICATES (Let's Encrypt)
----------------------------------------------------------------

  sudo certbot --nginx -d olracads.com -d www.olracads.com
  sudo certbot --nginx -d admin.olracads.com

  # Verify auto-renewal timer is active:
  sudo systemctl status certbot.timer


================================================================
PART B — GITHUB ACTIONS CI/CD (AUTO-DEPLOY ON PUSH)
================================================================

After the server is fully set up, configure GitHub Actions so
every push to main automatically builds and deploys.

----------------------------------------------------------------
STEP 10 — ALLOW GITHUB ACTIONS TO WRITE TO WEB ROOT
----------------------------------------------------------------

On EC2, give ubuntu ownership of the web root so the deploy
script can copy files without sudo for each cp:

  sudo mkdir -p /var/www/olrac/client /var/www/olrac/admin
  sudo chown -R ubuntu:ubuntu /var/www/olrac

Allow ubuntu to restart the backend service without a password
prompt (required for non-interactive CI/CD):

  sudo visudo

Add this line at the bottom:

  ubuntu ALL=(ALL) NOPASSWD: /bin/systemctl restart olrac-backend, /bin/mkdir, /bin/cp, /bin/rm

Save and exit (Ctrl+X, Y, Enter in nano).


----------------------------------------------------------------
STEP 11 — ADD GITHUB SECRETS
----------------------------------------------------------------

In GitHub -> your repo -> Settings -> Secrets and variables
-> Actions -> New repository secret. Add these secrets:

  Secret Name          | Value
  ---------------------|-----------------------------------------------
  EC2_HOST             | Your EC2 Elastic IP (e.g. 13.235.xx.xx)
  EC2_USER             | ubuntu
  EC2_SSH_KEY          | Contents of your .pem private key file
                       | (open the .pem file, copy ALL text including
                       |  -----BEGIN RSA PRIVATE KEY----- lines)
  VITE_CLIENT_SITE_URL | https://olracads.com
  VITE_ADMIN_SITE_URL  | https://admin.olracads.com


----------------------------------------------------------------
STEP 12 — GITHUB ACTIONS WORKFLOW
----------------------------------------------------------------

The workflow file is already in the repo at:
  .github/workflows/deploy.yml

It builds both frontends with the correct VITE_ env vars,
copies them to the EC2 instance, and restarts the backend.
No further changes needed once the secrets above are set.


================================================================
PART C — UPDATING THE APP IN THE FUTURE
================================================================

With CI/CD active, the workflow is simply:

  1. Make code changes locally
  2. git add . && git commit -m "your message"
  3. git push origin main
  4. GitHub Actions builds and deploys automatically (~2-3 min)

To monitor a deploy:
  GitHub -> your repo -> Actions tab -> latest workflow run

To check backend logs on EC2:
  sudo journalctl -u olrac-backend -f

To manually restart backend on EC2:
  sudo systemctl restart olrac-backend
